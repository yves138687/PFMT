# Personal Knowledge System 项目迭代规划文档

## 1. 文档说明

### 1.1 目的
本文档用于定义 `Personal Knowledge System` 的项目推进节点与迭代计划，明确每个迭代要实现的核心功能、交付结果和完成标准，方便后续按阶段推进开发。

### 1.2 规划原则

- 优先实现最小可用闭环
- 优先实现单用户与低资源环境可部署版本
- 优先实现文件管理、加密存储、基础展示
- AI 能力只做受控范围，不做全局检索
- 富文本、视频、PDF 等能力放到后续迭代逐步补齐

### 1.3 当前规划基线

- 当前日期：`2026-07-23`
- 部署目标：单机、自托管、`2U2G` 低资源环境可运行
- 技术基线：`Vue 3 + TypeScript + FastAPI + Python + SQLite`

---

## 2. 总体推进思路

项目建议分为 6 个迭代推进：

1. 迭代 0：技术基建与项目骨架
2. 迭代 1：最小可用版本 MVP
3. 迭代 2：文件展示与目录增强
4. 迭代 3：受控 AI 能力接入
5. 迭代 4：编辑体验与备份能力增强
6. 迭代 5：多媒体能力与产品完善

建议节奏：

- 每个迭代尽量控制在 `1 ~ 2 周`
- 每个迭代结束时必须有可运行版本
- 先交付功能闭环，再优化交互和体验

---

## 3. 迭代总览

| 迭代 | 阶段目标 | 核心关键词 | 优先级 |
| --- | --- | --- | --- |
| 迭代 0 | 搭建开发与运行基础 | 项目骨架、数据库、存储目录、认证基础 | P0 |
| 迭代 1 | 形成最小可用闭环 | 登录、文件树、上传、加密、展示 | P0 |
| 迭代 2 | 完善基础文件管理 | 路径分类、隐藏规则、搜索、标签 | P1 |
| 迭代 3 | 接入受控 AI | 指定文件、当前文档、指定段落、`@文件` | P1 |
| 迭代 4 | 增强编辑与恢复能力 | Markdown、备份、恢复、摘要管理 | P2 |
| 迭代 5 | 完善多媒体与体验 | 富文本、PDF、视频、审计优化 | P2 |

---

## 4. 迭代 0：技术基建与项目骨架

### 4.1 目标
完成前后端项目初始化、数据库初始化、文件存储目录规划、基础开发规范与可运行的空骨架。

### 4.2 需要实现的功能

- 前端项目初始化
- 后端项目初始化
- 基础路由与页面框架
- 数据库初始化
- 本地文件存储目录初始化
- 基础配置管理
- 日志基础封装
- 健康检查接口

### 4.3 交付结果

- `web` 与 `server` 两个项目可独立启动
- SQLite 数据库可自动初始化
- `storage/objects`、`storage/temp`、`storage/backups` 目录建立完成
- 有基础首页、登录页、空白知识库页

### 4.4 完成标准

- 本地一键启动成功
- 前后端能连通
- 健康检查接口返回正常
- 基础配置可通过 `.env` 管理

---

## 5. 迭代 1：最小可用版本 MVP

### 5.1 目标
完成第一个真正可用版本，让用户可以登录、管理文件树、上传文件、加密保存文件并进行基础展示。

### 5.2 需要实现的功能

- 单用户简单登录
- JWT 登录态校验
- 文件树基础结构
- 普通路径创建
- 私密路径创建
- 文件上传
- 文件本体加密存储
- 存储对象名随机化
- 文件元数据入库
- 文件列表页
- 文件基础详情页
- 图片基础展示
- 文本文件基础读取展示
- 基础下载能力

### 5.3 暂不实现

- 富文本编辑
- PDF 在线预览
- 视频播放优化
- AI 功能
- Git 备份

### 5.4 交付结果

- 用户可完成登录
- 用户可创建目录
- 用户可上传文件
- 文件会以加密形式写入存储层
- 文件名不会直接暴露在存储对象名中
- 用户可看到文件树和文件基础信息

### 5.5 完成标准

- 至少支持 `Markdown / txt / png / jpg / pdf / mp4` 上传
- 上传后数据库和存储对象映射一致
- 小文件可以正常预览或基础读取
- 登录后才能访问业务页面

---

## 6. 迭代 2：文件展示与目录增强

### 6.1 目标
完善路径管理、隐藏规则和元数据搜索，让系统真正具备“管理知识资产”的基础能力。

### 6.2 需要实现的功能

- 树状目录展开与折叠
- 路径移动与重命名
- 文件重命名
- 隐藏目录
- 隐藏文件
- 显示隐藏内容开关
- 隐藏展示时效控制
- 标签管理
- 元数据搜索
- 搜索筛选：路径、标签、文件类型、时间
- 文件摘要字段展示

### 6.3 交付结果

- 普通路径 / 私密路径管理能力可用
- 文件和目录支持隐藏与展示切换
- 元数据搜索可用
- 标签筛选可用

### 6.4 完成标准

- 隐藏内容默认不出现在文件树和搜索结果
- 开启“显示隐藏内容”后可临时查看隐藏项
- 搜索结果仅基于文件名、标签、摘要、路径等元数据

---

## 7. 迭代 3：受控 AI 能力接入

### 7.1 目标
在不破坏隐私边界的前提下，接入用户显式授权范围内的 AI 能力。

### 7.2 需要实现的功能

- AI 配置页
- OpenAI Compatible API 接入
- 指定文件总结
- 当前打开文档问答
- 指定段落润色
- 指定段落替换
- 指定段落翻译
- 指定段落续写
- `@文件` 引用
- AI 可读取范围提示
- AI 调用日志

### 7.3 关键限制

- 不支持 AI 全局检索知识库
- 不支持后台自动扫描全文
- 不支持未授权文件自动进入上下文

### 7.4 交付结果

- 用户可以基于当前打开文档与 AI 对话
- 用户可以对选中段落发起编辑类 AI 请求
- 用户可以显式选择文件或 `@文件` 让 AI 总结

### 7.5 完成标准

- 每次 AI 调用前后都能明确看到可读取范围
- 当前文档 AI 问答不会扩展到其他未指定文件
- AI 结果支持复制或回填

## 8. 迭代 4：编辑体验与备份能力增强

### 8.1 目标
增强文档编辑体验，并补齐可恢复、可迁移的备份能力。

### 8.2 需要实现的功能

- Markdown 编辑
- 自动保存
- 文档历史版本基础能力
- 人工摘要编辑
- AI 摘要生成并保存为元数据
- Git 备份
- 备份包导出
- 备份级加密开关
- 备份日志
- 手动恢复
- 恢复预览
- 对象映射清单恢复链路

### 8.3 交付结果

- Markdown 文档可编辑并保存
- 文件可备份到 Git
- 数据库损坏场景下具备恢复预案

### 8.4 完成标准

- 至少完成一次从备份包恢复的验证
- 备份包包含元数据、对象映射、文件密文、配置项
- 编辑器具备基础可用性

## 11. 迭代验收建议

每个迭代结束时建议固定做以下检查：

### 11.1 功能验收

- 是否完成本迭代范围内的核心功能
- 是否有可运行版本
- 是否有最小操作闭环

### 11.2 技术验收

- 是否符合低资源部署要求
- 是否新增了不必要的重型组件
- 是否破坏文件加密或 AI 权限边界

### 11.3 文档验收

- PRD 是否需要同步更新
- 技术架构文档是否需要同步修订
- 数据库或 API 设计是否需要补文档

---

## 12. 当前建议结论

当前最合理的推进顺序是：

1. 先完成迭代 0 和迭代 1，形成真正可用的加密文件管理闭环
2. 再做迭代 2，把隐藏规则、标签和搜索补齐
3. 然后做迭代 3，在受控范围内接入 AI
4. 最后再逐步补齐编辑、备份、多媒体能力

这样做的好处是：

- 开发节奏清晰
- 风险可控
- 不会一开始就被 AI、视频、富文本这些复杂能力拖住
- 可以尽快拿到一个可运行、可验证、可继续演进的版本
